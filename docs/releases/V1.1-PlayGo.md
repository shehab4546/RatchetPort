# V1.1 PlayGo — Pre-Alpha build

This build addresses the observed `scePlayGoPrefetch` unsupported-import stop.
It does **not** establish successful game startup or stable gameplay. V1 remains
unchanged; CI produces a separately named, commit-specific Windows artifact.

## Confirmed defects

At baseline `146e6cbb5116aced91c9f02ca26ba75261f97525`, the import-name map
contained Prefetch (`-Q1-u1a7p0g`) and GetEta (`v6EZ-YWRdMs`), but the runtime
service export table did not implement them. A missing `playgo-chunk.dat` was
silently represented as one fully installed chunk. Preflight did not require the
file. Sc0 discovery stopped at a valid destination SFO, and the Play button did
not invoke the existing system-file adoption flow.

The supplied RTX 5070 Laptop log shows a missing PlayGo file, the fabricated
one-chunk state and then the Prefetch trap (exit 20). The missing file causing the
game to choose Prefetch remains a hypothesis; no controlled game A/B run has been
performed here. This work changes no renderer settings or GPU fixes.

## Behavior

- Prefetch and GetEta resolve through the production runtime resolver. A valid
  installed-chunk request returns success; GetEta writes a signed 64-bit zero.
  State, handle, null pointers, counts, chunk IDs and locus are checked. Errors do
  not partially write ETA/output arrays. Unknown imports remain unsupported.
- Initialization validates the API workspace parameters and a complete 256-byte
  PlayGo header, file length, count limits, table bounds/alignment and overlapping
  sections. Missing/invalid metadata leaves the service uninitialized. No count
  is fabricated or fixed to this game's observed 72 chunks.
- Launcher and command-line preflight require valid `sce_sys/playgo-chunk.dat`
  and name its absolute host path on failure. The runtime reports its guest path.
  Header validation is not verification of every game asset or table payload.
- The launcher offers Sc0 adoption before preflight, even when param.sfo exists.
  Source SFO must identify CUSA01047 / 01.00 and match an existing destination SFO
  (including CONTENT_ID when present). Separate update sources are rejected.
  Source identity is checked again when copying. Valid destination files are
  preserved; unreadable files are never overwritten; copies are checked before
  atomic replacement. No game files are shipped or downloaded.
- Prefetch list sizes are bounded to the supported 1000-chunk domain before
  dereferencing entries. Duplicate valid IDs are accepted. This is the runtime's
  bounded installed-dump policy, not a claim that the original API forbids every
  larger duplicate list. Existing completed progress representation stays 1/1.

## Restoring the missing file

For the selected game directory `<game>`, the required destination is:

```
<game>/sce_sys/playgo-chunk.dat
```

For an extracted `Image0` / `Sc0` layout, use `Sc0/playgo-chunk.dat` from the
**same original CUSA01047 USA v1.00 dump**. The launcher offers to copy it into
`Image0/sce_sys/playgo-chunk.dat` after verifying Sc0's param.sfo. Do not obtain
metadata from another title, region or update. Do not manufacture a header or
change the chunk count. If Sc0 lacks this file, restore/re-extract it from your
own original dump.

## Validation and limits

- `test_playgo.c` links production `runtime.c`, `runtime_services.c` and
  `runtime_file.c`; only unrelated GPU/service backends are substituted. This
  covers actual scoped NID resolution, invocation ABI, state transitions,
  argument failures, unchanged outputs on failure and real fixture-file I/O.
- `test_playgo.py` checks synthetic valid metadata, missing metadata and 19
  malformed forms (including truncation, overflow and overlapping tables).
  `test_playgo_sc0.py` covers valid-SFO/missing-PlayGo repair, wrong identities,
  invalid metadata, repeated copies, file preservation and Play-button ordering.
- Local GCC builds use `-Wall -Wextra -Werror`. The services test passes.
  The focused Python suite ran 79 tests, passing with 5 Windows-only skips.
- AddressSanitizer and UndefinedBehaviorSanitizer passed the six PlayGo test
  methods (including the malformed-file subcases). Leak detection could not run
  in this execution host (`/proc`/ptrace limitation), so that check was disabled
  explicitly; no leak-check success is claimed.
- The local full Python run executed 463 tests with 95 skips; one failure and
  three errors reproduce unchanged on the baseline (450 tests, same 95 skips):
  two Windows filesystem mocks on Linux, Windows-only package path auditing,
  and an older mod-runner fixture with an empty preparation module. They are
  not treated as successful checks or hidden by exclusions in Windows CI.
- Windows CI runs the existing build, the native PlayGo/services tests, the full
  Python suite, packaging/source audit and the existing isolated package smoke
  test. Consult that run's result; launcher smoke is not game-play evidence.
- No PS4 game data or actual game session is available in this validation
  environment. Reaching gameplay, rendering, saves and long sessions are unverified.
