# V1.4 — Frame Timing Preview

An opt-in 60 FPS timing experiment for the exact reviewed CUSA01047 USA 01.00
build. Original/30 remains the default. This preview is not gameplay-accepted.

- Home / Performance: choose **Game frame rate → 60 FPS (experimental)**, then
  close and restart the game. The patch changes guest pacing and clock initialization
  together. A host cap alone does not enable the feature.
- Unknown hashes or changed bytes reject the whole group and retain the 30 ceiling.
  Native transaction failure aborts before guest execution. Original plus restart
  removes both patches without modifying game files.
- Host vblank remains 60 Hz. Inherited live FPS writes/cycling are disabled.
- Requested mode survives saving settings from the in-game overlay. The overlay
  distinguishes a nominal target from measured throughput.
- Window title, executable metadata and archive names identify V1.4 consistently.

The isolated clock experiment passed 16 deterministic cases, including frame drops,
smoothing, pause and slow motion. It does not test gameplay, audio or cutscenes.
Windows CI results are recorded on the implementation PR and attached provenance
when a build is published. Do not infer validation from this document alone.

For acceptance, compare the same scene/save at Original/30 and experimental60.
Check real-time movement and cooldowns, physics, audio/cutscenes, save/load and
pause/resume. Preserve each run's user/last_run.log and out/patch_status.json.
See [detailed evidence and test procedure](../RP04_FRAME_TIMING.md).

Motion-blur and internal-resolution patches remain disabled. No 120 FPS mode,
tearing fix, cutscene-stutter fix or sustained frame rate is claimed. No game
files are included. Use your own matching dump.
